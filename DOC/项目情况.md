# 项目情况

把 2048 底座上已经接好的 ILI9488 做成 Luckfox Lyra B 的 Linux 控制台。改动在 Luckfox 内核里，不改 2048 工程，不跑 2048，不给 Pico 刷 UF2。摇杆不要接：排针 31、32 是 1.8 V 的 SARADC。

## 这块板子现在是什么

| 项目 | 情况 |
| --- | --- |
| 板子 | Luckfox Lyra B，RK3506G2 |
| 系统 | SD 卡上的 Ubuntu 22.04.5 LTS，不是板载 SPI NAND 里的 Buildroot |
| 内核 | `6.1.99`，2025-04-17 编译，`arm-none-linux-gnueabihf-gcc 10.3.1` |
| 根文件系统 | `/dev/mmcblk0p3`，ext4 |
| 启动分区 | `/dev/mmcblk0p2`，约 12 MB，里面是 FIT：设备树加 zImage |
| 启动参数 | `storagemedia=sd root=/dev/mmcblk0p3 rootfstype=ext4`，控制台 `tty1` 和 `ttyFIQ0` |
| 登录 | 镜像里写的是 `root` / `root`，`lyra` / `luckfox`。ADB 进去已经是 root |
| USB | Type-C 是 RNDIS + ADB。板子地址 `192.168.123.100`。ADB 需要厂商号 `0x2207` |
| 串口 | 排针 1 为 TX，排针 2 为 RX |

出厂内核没有 `panel-mipi-dbi`，也没有 GPIO 背光。只换设备树点不亮这块屏，必须重编内核，并把 `ili9488.bin` 编进内核。板子内存大约 87 MB，上面编译不了。编译用的交叉编译器是 Linux x86_64 程序，这台 Apple 芯片的 Mac 也跑不了。

## 屏怎么接

6 线 SPI，模式 0，没有 MISO。最高 20 MHz。横屏，点阵 8×16。

| 信号 | 排针 | 引脚 | 说明 |
| --- | --- | --- | --- |
| RST | 20 | GPIO0_A2 | 低电平复位 |
| 背光 | 21 | GPIO1_D3 | 高电平点亮 |
| CS | 22 | GPIO1_D2，RMIO30 | SPI0_CSN0，功能号 85 |
| SCK | 24 | GPIO1_D1，RMIO29 | SPI0_CLK，功能号 82 |
| MOSI | 25 | GPIO1_C3，RMIO28 | SPI0_MOSI，功能号 83 |
| DC | 26 | GPIO1_C2 | 高电平为数据 |

功能号是 TRM 里的序号加 15。这几组 GPIO 的 iomux 是 4 位，驱动实际写入的是 `mux - 15`。SDK 里已有的 I2C2 也是这么写的。

初始化序列来自 2048 工程的 `ili9488_driver.cpp`。`0x36` 从竖屏的 `0x48` 改成横屏的 `0x28`（MV + BGR）。`0x3A` 保持 `0x66`，也就是 RGB666，不要写成 `0x55`。

## 仓库里有什么

这个 Git 仓库只放补丁和说明，不放 SDK。SDK 压缩包大约 3 GB。

| 路径 | 作用 |
| --- | --- |
| `patches/0001-drm-mipi-dbi-rgb666.patch` | 给 6.1 的 `panel-mipi-dbi` 补上 RGB666 |
| `patches/0002-arm-dts-luckfox-lyra-ili9488.patch` | 在 `rk3506g-luckfox-lyra.dts` 上关 DSI、开 SPI0、接这块屏 |
| `patches/0003-arm-dts-luckfox-lyra-sd-ili9488.patch` | 旧 SDK 才有的 `rk3506g-luckfox-lyra-sd.dts`。202610 已经没有这个文件，`apply.sh` 会跳过 |
| `firmware/ili9488.txt`、`firmware/pack.py`、`firmware/ili9488.bin` | 屏的初始化固件，79 字节 |
| `configs/ili9488.fragment` | 要编进内核的配置 |
| `apply.sh` | 打补丁、拷固件、合并配置 |
| `Luckfox-Lyra-ILI9488主屏移植.md` | 原来的移植说明 |
| `DOC/Linux编译操作指导.md` | 在 Ubuntu 上编内核的步骤 |

## 已经对过的源码

用的 SDK 是 `Luckfox_Lyra_SDK_202610.tar.gz`，SHA256：

```text
74f1379cbf4968f566b3a5385010ead076cc65bbee838b83e72a5f996494b3c9
```

清单是 `luckfox_linux6.1_rk3506` 这一支，内核目录是 `kernel-6.1`。202610 把 SD 卡和 SPI NAND 合成了同一份 `rk3506g-luckfox-lyra.dts`，设备树里不再写 `root=`。现在这块板的 U-Boot 仍会带上 `root=/dev/mmcblk0p3`。

RGB666 补丁和这份设备树已经在 Mac 上对 202610 的源码试用过，`apply.sh` 可以打进去。内核还没有编出来，也还没有往板子上刷。

和原始移植说明有两处不同，按 6.1 驱动改的：

- 像素格式用 `b6x2g6x2r6x2`。驱动按小端、8 位一字送出 RGB888，线上就是 B、G、R，和 `0x36 = 0x28` 的 BGR 一致。文档里的 `r6x2g6x2b6x2` 这份驱动不认。
- `hsync-len` 和 `vsync-len` 都是 0。写成 1 时，探测会报 `panel-timing out of bounds`。

## 编译时不要做的事

202610 的 lunch 只有 Buildroot，没有单独的 Ubuntu 选项。这块板现在跑的是 SD 卡上的 Ubuntu。

只编内核，得到 `boot.img`。不要编、不要刷 Buildroot 的根文件系统，否则会盖掉现在的 Ubuntu。`getty@tty1` 在现有镜像里已经打开，不用改 Buildroot 的 inittab。

刷写不在这次编译步骤里。现有启动分区要先留备份，再只替换 `/dev/mmcblk0p2`。
